The compile order

The compiler builds the graph in this order. Do not skip ahead.

1 · Gather user input

Collect the instruction pack once — company background, offer and proof, ICP, persona, tools, volume, and send policy. This pack feeds every later step. Never ask for API key values here: provider and access level only.

2 · Create the trigger

Two trigger families, one primary path per run: a scheduled data-tool search on your ICP and signals, or a webhook that fires when you upload a CSV. Both write a company table, filtered against CRM stages so you never re-work live deals.

3 · Configure data

Company enrich plus people search on the company table. JSON filters from your intake — departments, titles, signals — with a hard cap of N contacts per company. Output: the contact table.

4 · Configure CRM

Batch create-or-update contacts, matched on email or domain + name. Writes CRM ids back onto the row. No enrollment from this node — this is the write step; the trigger filter was the read.

5 · Configure research

AI node plus web search, with a system prompt compiled from your intake. Pulls company, product, team, and news datapoints and drafts a pain-point hypothesis as structured JSON. Separate node from email — never collapse research and copy.

6 · Configure messaging

System instructions compiled from the same intake produce the campaign copy: emails 1–7 (subject + body) plus LinkedIn connection note, DM, and InMail. One node returning JSON for the full set — cheaper and easier to test. Copy only, no send.

7 · Configure sequence enrollment

Bind enrollment: sequence, list, or mailbox send (Resend, Gmail, custom API) mapped to a specific inbox. If you have no outreach tool, keep the copy and stop after step 6.

What a compiled run delivers

  • company_table — name, domain, url, linkedin_url, crm_stage, source.
  • contact_table — name, title, email, phone, linkedin, company_domain, crm_id.
  • research_object — datapoints, pain-point hypothesis, value proposition.
  • campaign_copy — emails 1–7 with subject + body, LinkedIn connect / DM / InMail.
  • enroll_receipt — tool, sequence or list, inbox, status (when step 7 is armed).
  • Build package — workflow.json, the n8n Engineer skill that can edit it, both AI system prompts, credential instructions, and a test checklist.

The quick test (required before done)

  • 1 — Dry-run the trigger with a limit of one company.
  • 2 — The company table row exists, and the CRM filter didn't drop a clean account.
  • 3 — At least one contact with an email, or a typed skip reason.
  • 4 — The CRM upsert returned an id, or a typed skip.
  • 5 — The research JSON contains a pain-point hypothesis.
  • 6 — Email 1 has a subject and a body.
  • 7 — Sequence / send stays OFF in test unless you explicitly arm it.

Fail any assertion, ship nothing

If the quick test fails, the JSON doesn't ship as successful — you get the node error and a patch plan instead.
