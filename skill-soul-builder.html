How it works

Provide input

Agent name, archetype, brand voice, core values, constraints, domain, response patterns, personality traits.

Generate the soul package

Granular brand voice (formality, enthusiasm, humor, empathy scales), hard constraints — max outreach per day, working hours, no-send rules, never exaggerate product.

Validate

Safety + bias checks with a validation report and good/bad response examples.

Inject

Inject the soul into a running agent via CLI, with an integration guide.

A/B test souls

Run competing souls against each other and keep the winner.

Outputs — what's in the soul package

  • system_prompt.txt — the agent's core identity.
  • behavior_rules.json — constraints, limits, and guardrails.
  • response_templates.json — objection handling + meeting scripts.
  • personality_matrix.json — the voice, quantified.
  • integration_guide.md — how to inject and run it.
  • validation_report.json — safety and bias results.
  • Good / bad response examples + edge cases — so you know exactly what "on-soul" looks like.
