Case studies

Production systems, explained step by step.

No vanity metrics — just how each system works: what problem it solves, what was built, and the mechanism that keeps it trustworthy. Two kinds of proof: systems Patrick built and operated in production at Atlas HXM, and Prospect Automation Engine deployments for Salesgency clients.

Flagship · built & operated by Patrick Diamitani, GTM AI & Automation Manager, Atlas HXM

AI inbound lead automation — how every submission gets triaged.

P

The problem

Atlas HXM's inbound "Contact Us" leads sat untriaged — no instant qualification, no routing, and no way to prove what marketing automation was worth. Sales-ready buyers waited in line behind job seekers, verification requests, and press inquiries.

B

What was built

A multi-node n8n workflow: every form submission is classified by an AI agent into intent categories, the MQL lifecycle stage is set in HubSpot, partnerships route to the right owner, and a grounded reply agent answers sales-ready leads referencing the country and service they asked about.

R

How it stays trustworthy

A measurement pipeline matches every workflow execution against live CRM deals — a deal counts only if it was created on or after the contact's workflow run, so pre-existing deals are excluded by construction. Every outcome traces back to a specific execution ID.

Stack: n8n · Azure OpenAI · Azure AI Search · HubSpot CRM + API · Microsoft Outlook · Claude (agentic analysis) · Python.

AI customer agent

How a chat becomes a traceable deal

Problem: site visitors bounced without qualifying; nobody could prove the agent's revenue impact.

Built: a production agent on the public pricing page with versioned guardrails and every execution logged, plus a recurring attribution stamper that writes sourced and influenced tiers onto deals.

How it works: any deal can be traced back to the originating chat thread — qualification happens in the open, and the CRM record shows exactly which conversation sourced it.

Prospect data pipeline

How an agency gets clean contacts, never burned ones

Problem: feeding an outsourced SDR agency stale or already-called contacts burns money and brand.

Built: a Python pipeline merging multiple enrichment exports, deduped against every contact the agency ever called, with buying-intent signals pulled from hiring platforms.

How it works: only unique, verified contacts survive — tier-ranked into weekly call plans, with mobile coverage confirmed before a number ever reaches the agency.

AI compliance screening

How deals get screened before signature time

Problem: deals reached contract stage before anyone checked regulatory eligibility — blockers surfaced at signature time.

Built: a system mapping messy CRM data to a sector rulebook, with a deterministic, unit-tested rules engine issuing the verdict.

How it works: every open deal is screened the same way, wrongly-stuck deals get cleared with a recorded reason, and ineligible deals are flagged early — the rules decide, not someone's memory.

Contract intake

How a deal reaches legal without retyping

Problem: sellers hand-copied deal data into Legal's e-signature form; errors stalled contracting.

Built: the seller pastes a deal URL, an agent confirms the details in a few steps, and an AI browser agent pre-fills the form in the seller's own logged-in browser — Legal's process untouched, the agent never clicks submit.

How it works: the human reviews the pre-filled form and submits it themselves — automation does the copying, people keep the authority.

Post-call automation

How every sales call gets a follow-up without rep effort

Problem: reps left calls without follow-ups; country-specific facts were applied inconsistently.

Built: an always-on pipeline triggered after every call — country-aware follow-up email, missed-questions analysis, competitor research, LinkedIn draft, plus an automatic CRM note. Zero rep action.

How it works: the transcript flows through a fixed sequence of agents, each with one job, and everything lands in the CRM where the rep can see and correct it.

Cost governance

How enrichment spend stays predictable by design

Problem: runaway enrichment spend — background workflows burned through a large credit purchase unmonitored.

Built: a standard, cloneable enrichment table — a free ICP-fit gate before any paid column, AI columns restricted to top-tier accounts, per-row cost estimates, and spend reports to the budget owner.

How it works: cost control is enforced by structure, not by asking users to be careful — the table simply won't spend on accounts that don't qualify.

Enterprise robotics · custom engagement

How plant managers got onto demo calls

Problem: an industrial robotics company couldn't get C-level plant managers onto demo calls.

Built: a custom Prospect Automation Engine with automated funding and expansion signal ingestion feeding the target stage.

How it works: buying signals surface the right accounts, the engine researches each one, and personalized outreach goes out under human approval — demos get booked while the team watches the run ledger.

Global logistics · CRM shield architecture

How outbound runs without deal collisions

Problem: a large corporate contact base with frequent SDR deal collisions on key accounts.

Built: a fault-tolerant CRM shield filtering all outbound against active pipelines, with real-time verification before sequencing.

How it works: the shield stage removes anything touching an open deal before a contact is ever revealed — sender reputation holds because bad addresses and collisions never enter a sequence.

Generative AI SaaS · managed agent

How technical outreach gets personal at scale

Problem: reaching engineering leaders with credible, technical outreach at scale.

Built: a managed cloud agent performing deep repository and tech-stack analysis to generate hyper-personalized outreach.

How it works: the research stage reads what the prospect actually builds with, the write stage turns that into specific outreach, and meetings get booked without a rep writing a single first draft.
